# Lesson 30: Expressions and JIT C++

{% include lesson_meta.html %}

> **Before this lesson** finish [Lesson 29]({{ site.baseurl }}/learn/29-javascript-processes.html).
>
> **You will need** a device with a few parameters, and speakers or headphones.
>
> **You will build** three small computations: a mapping written as a formula, an array generated by expression, and a sound produced by arithmetic.

## Why this matters

Lesson 29 showed the general-purpose escape hatch. This lesson covers the specific ones, and the reason to prefer them is that a smaller tool is easier to read, faster to run, and harder to get wrong. A relationship that is genuinely a formula should be written as a formula: `sqrt(x) * 0.8 + 0.1` is clearer than a drawn curve approximating it and clearer than twelve lines of script.

The lesson also introduces the idea of compiled code inside a document, which sounds heavy and is not. A just-in-time compiled expression runs at full speed on the machine it is running on, which matters when a computation happens per audio sample or per pixel rather than per tick.

## Concepts

**Math expression processes.** A family of objects that evaluate a written formula. The smallest, usually called a micromap, multiplies and offsets in one step, which is the most common conditioning operation in the whole course and appeared in Lesson 28. The fuller expression objects take arbitrary formulas with variables, functions, and conditionals.

**Array generators and mappers.** Expression objects that produce or transform arrays rather than single values. An array generator returning `[cos(2*pi*i/n), sin(2*pi*i/n)]` lays out points on a circle, which is exactly the speaker-layout trick from Lesson 22 and the geometry trick from Lesson 27. An array mapper applies a formula element-wise.

**Bytebeat.** A generator that produces audio from a formula over a sample counter. It is a small, strange, and instructive corner of computer music: a handful of arithmetic operations on an integer produce rhythmic, harmonic material. Its practical value here is pedagogical, since it makes the relationship between arithmetic and sound immediate.

**Just-in-time compiled C++.** A process whose script is C++, compiled when you press compile, and then run natively. Reach for it when a computation must happen very often, per sample or per element in a large array, and when the expression objects are not enough. It is also the route to using an existing algorithm you have in C++ without building a plug-in.

**The same editor, the same loop.** All of these use the script editor and its compile action, `Ctrl+Enter`, with invalid code refused rather than applied, exactly as Lesson 26's shaders did. Learn the loop once and it serves every scripting route.

**Cost, honestly.** An expression evaluated per tick is free in any practical sense. The same expression per audio sample is a different proposition, and per pixel it belongs in a shader rather than here. Knowing which rate a computation runs at is what tells you which tool it needs.

## Walkthrough: three computations

1. **Start with the smallest.** Insert a micromap between a sensor value and a destination and set a multiplier and an offset. This is the conditioning stage of Lesson 13 in one object.
2. **Write a real formula.** Replace it with a full expression object and write a relationship that is not a straight line, a square root or a squared curve, and compare the feel with the mapping curve you drew in Lesson 13.
3. **Note which is more readable.** For a collaborator, a drawn curve is often clearer; for you, a formula is exact and reproducible. Both are defensible, and it is worth having an opinion.
4. **Generate an array.** Use an array generator to produce eight positions on a circle, and view them with a point view. You now have a parametric layout, which is the Lesson 22 recommendation implemented.
5. **Automate the parameter.** Automate the count or the radius so the layout changes over the piece, which no hand-placed set of points can do.
6. **Map an array element-wise.** Add an array mapper that scales every element, and confirm with the point view.
7. **Make sound from arithmetic.** Add a bytebeat process, listen to the default, and change one constant. This is the fastest available demonstration that sound is arithmetic.
8. **Write a C++ process.** Add a just-in-time C++ process and implement a computation of your own, however small: a soft clipper, a running average, a threshold with hysteresis. Compile and cable it in.
9. **Break it.** Introduce a compile error and confirm the running document is unaffected, and that the error appears in the editor's pane.
10. **Compare rates.** Put the same computation in an expression object and in the C++ process, at control rate, and note that both are fine. Then consider what changes if it ran per audio sample: this is the judgement the lesson is teaching.

## Choosing among five routes

By the end of Module J you will have five ways to write behaviour. This is the decision, in one place.

**A utility process** when one exists. Visible, no code, no compile step.

**A math expression** when the behaviour is a formula over a few values. Small, exact, and readable by anyone who reads arithmetic.

**JavaScript** when the behaviour needs state, conditionals, or generation, and runs at control rate. The most flexible, the least fast, and the easiest to write.

**Faust**, in [Lesson 31]({{ site.baseurl }}/learn/31-faust.html), for anything that processes audio signals. It is designed for exactly that, it compiles for the machine, and it brings a large library.

**Just-in-time C++** when none of the above fits: an existing algorithm, an unusual data structure, or a computation whose rate makes the others too slow.

A useful ordering heuristic: try them in that order and stop at the first that works. The temptation runs the other way, because the powerful tools are more interesting, and the resulting document is harder for anyone else to read.

## Rates, and why they decide the tool

The single most useful idea in this lesson is that every computation happens at a rate, and the rate determines which tool is appropriate.

**Per tick**, the control rate, perhaps a few hundred times a second. Anything works here: an expression, a script, a chain of utility objects. Choose for readability, not for speed.

**Per audio sample**, tens of thousands of times a second. A control-rate tool used here is either impossible or badly aliased. This is Faust's territory, or compiled C++.

**Per pixel**, potentially millions of times per frame. This belongs in a shader, per Lesson 26, and nothing in this lesson is the right answer.

**Per element of a large array**, which is somewhere between the second and third. The array-aware expression objects handle moderate sizes; a compute shader handles large ones.

Asking "how often does this run" before "what should I write it in" makes the choice almost automatic, and it explains why the same formula belongs in three different places depending on where in a document you need it.

## Common mistakes

- **A script where a micromap would do.** The most common over-engineering in this software.
- **A drawn curve approximating a formula you already know.** If you can write it, write it.
- **Hand-placing points that an expression could generate.** Then the layout cannot be automated or reused.
- **Per-sample work in a control-rate tool.** It will either be slow or aliased; use Faust or C++.
- **Per-pixel work anywhere but a shader.** Lesson 26 is the right place.
- **Forgetting to compile.** Every scripting route shares this failure.
- **Reaching for C++ first.** It is the last resort for a reason: the compile step and the debugging cost are real.

## Exercise

Implement the same relationship three ways: as a drawn mapping curve, as a written expression, and as a just-in-time C++ process. Drive the same destination with each and confirm they agree. Then write two sentences: which you would ship in a document a collaborator will edit, and which you would ship in an installation that must run for a month.

**Success criterion:** all three produce the same output for the same input, and your two sentences give different answers with reasons. Then generate an eight-point circular layout by expression and automate its radius; if you hand-placed anything, you missed the point of the array generators.
